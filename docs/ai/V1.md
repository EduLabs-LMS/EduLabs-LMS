# V1: definition and checklist

Branches: all feature work branches from `claude/teacher-v1` and is merged back into it only after the owner approves. Nothing here
goes to `main`, and no PR, deploy or migration happens without explicit owner approval.

## What V1 means

V1 is done when all four parts are done:

1. **The teacher UI is finished.** No "Coming soon" item is left in the teacher menu, and every screen in the list below exists.
2. **The Helper.** A spotlight tour that teaches teachers the UI. The design is decided (see the Helper section below); the build has not started.
3. **Our own password-reset page and a properly designed reset email.**
4. **Pre-launch work.** A full Arabic/RTL pass, a security review of the whole branch, and a plan for the production migrations.

## Helper (V1 part b): decided design

- **What it is:** a spotlight tour. The page is dimmed, the part being explained stays bright, the page scrolls to it, and a small box
  beside it has a title, one or two plain lines, "Step N of M", Back and Next (Done on the last step). Skip is visible on every step.
  Escape closes it.
- **Phone:** the box sits at the bottom of the screen so it never covers the highlighted part.
- **Arabic:** the layout mirrors and Back/Next swap sides.
- **First sign-in:** it runs automatically the first time a new teacher signs in, starting on Home: the menu, the main parts of Home,
  and the "?" button.
- **The "?" button:** every teacher page has a quiet outlined "?" button in the page header (top right of the title row on desktop; in
  the header bar beside the menu button on phone). It starts the tour for that page only.
- **Settings > My account** gets "Show the walkthrough again". Its design is pending.
- **Tour steps** are written per page after the final screens exist, in English and Arabic, without the forbidden teacher-facing terms.
  Each step must point at a real element of the page, so every new screen from now on marks its tour targets.
- **Open question (recorded, not decided): where the "seen" flag is stored.** Preferred: per teacher in the database, so it holds
  across devices. That needs a migration, and the owner must approve before any migration is written or applied.
- **Demo data:** any stored Helper data must extend the demo seed (the rule below) or be explicitly excluded with a reason.

- Each file is pinned in `.gitattributes` as `-text` and is LF only.

- An applied migration is never edited. A fix is a new migration that replaces the function (as 20261029120000 does for 20261027120000).
- Remote migration history is verified by the operator; the manager holds no database credential.

## Demo-data rule

Every teacher feature that stores data extends the demo seed in the same change: a new seed module, a bumped seed version, its tables
added to the `demo_seed_rows` allowed list in a new migration, and an update to docs/ai/DEMO_DATA.md. `scripts/demo-spaces.test.cjs`
checks that the SQL, the service constant and the document agree. Clear must also keep working for anything a teacher can add.
